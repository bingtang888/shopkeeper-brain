### 2.4 提示词工程

#### 2.4.1 提示词模板结构

<img src="images/4.提示词模版.jpg" style="zoom:50%;" />

每个区块为 LLM 提供不同维度的信息：参考内容是核心证据，历史对话提供多轮上下文，图谱关系补充结构化知识，商品名限定回答范围，用户问题明确回答目标。

#### 2.4.2 字符预算控制

LLM 有输入长度限制，需要控制提示词总长度：

```python
char_budget = self.config.max_context_chars  # 默认 12000

# 依次分配，优先级递减，前一个消耗后剩余预算传给下一个
context_str, char_budget = self._format_reranked_docs(docs, char_budget)   # 文档优先
history_str, char_budget = self._format_chat_history(history, char_budget)  # 历史次之
graph_str, char_budget = self._format_kg_triples(triples, char_budget)     # 图谱最后
```

| 优先级 | 区块 | 理由 |
|--------|------|------|
| 最高 | 检索文档 | 核心参考内容，直接决定答案质量 |
| 次之 | 历史对话 | 理解多轮对话上下文 |
| 最低 | 图谱关系 | 补充结构化信息，非必需 |

> **`used_chars += len(doc_entry) + 2` 中的 +2**：最后拼接时用 `"\n\n".join()`，每两篇文档之间插入两个换行符，预算计算时要把这 2 个字符也算进去。

#### 2.4.3 格式化结果示例

**检索文档：**

```
[1] [source=local] [chunk_id=chunk_001] [title=操作指导] [score=5.0600]
测量直流电压时，将旋钮转到DCV档位，红表笔接VΩmA孔，黑表笔接COM孔。

[2] [source=web] [url=https://example.com] [title=电压测量指南] [score=3.9600]
注意：测量前请确认档位与量程，避免误接导致损坏或触电。
```

> **元信息标签传给 LLM 的作用**：帮 LLM 判断文档可信度（高分 > 低分，local>web），以及在答案中标注引用来源。

**图谱三元组：**

```
[RS-12 数字万用表] 直流电压测量 -(USES_TOOL)-> 红表笔
[RS-12 数字万用表] 直流电压测量 -(HAS_STEP)-> 选择DCV档位
```

> **图谱三元组与检索文档的区别**：检索文档是原文段落（长文本），图谱三元组是结构化关系（短文本）。两者互补——文档提供详细描述，三元组提供关键关系链。

## 3. 历史会话管理（第二部分）

### 3.1 为什么需要历史会话

多轮对话场景下，用户经常使用代词或省略主语：

```
第一轮：用户问"RS-12 万用表怎么测电压？"  → 助手回答...
第二轮：用户问"那电阻呢？"                → "那"指的是 RS-12 万用表
第三轮：用户问"它的电池怎么换？"           → "它"指的是 RS-12 万用表
```

如果没有历史对话，LLM 无法理解"那"和"它"的指代对象。

### 3.2 历史对话在 pipeline 中的双用途

```
item_name_confirm_node
  │
  │  chat_history = get_recent_messages(session_id)
  │  ├── 用途1: 传给 LLM，做指代消解（"它" → "RS-12 万用表"）
  │  └── state["history"] = chat_history  ← 写入 state
  │
  v
  多路检索 → RRF → Rerank
  │
  v
answer_output
  │
  │  state.get("history")  ← 从 state 取出
  │  └── 用途2: 填入提示词【历史对话】区块，LLM 生成更连贯的答案
  │
  v
  LLM 生成答案
```

### 3.3 MongoDB 历史记录结构

```json
{
    "_id": ObjectId("69bbf91aaca1715a656e1590"),
    "session_id": "sess-2i16xujs1npmmxdcqhw",
    "role": "user",
    "text": "如何使用万用表测量电压",
    "rewritten_query": "如何使用万用表测量电压",
    "item_names": [],
    "ts": 1773926682.007168
}
```

| 字段 | 说明 |
|------|------|
| `session_id` | 会话 ID，同一浏览器标签页共享 |
| `role` | `user` 或 `assistant` |
| `text` | 消息内容 |
| `rewritten_query` | 重写后的查询（方便回溯） |
| `item_names` | 关联的商品名（可为空列表） |
| `ts` | 时间戳 |

### 3.4 历史记录读取：item_name_confirm_node 改造

```python
def process(self, state: QueryGraphState) -> QueryGraphState:
    session_id = state["session_id"]
    original_query = state["original_query"]

    # ★ 新增：从 MongoDB 查历史对话
    from knowledge.utils.mongo_history_utils import get_recent_messages, update_message_item_names
    chat_history = get_recent_messages(session_id, limit=10)
     #  构造历史对话文本
    history_text = ""
    for msg in chat_history:
    	role = msg.get("role")
        content = msg.get("text", "")
        history_text += f"{role}: {content}\n"
    

    # 2. 调用 LLM 提取商品名（★ 传入历史对话用于指代消解）
    clean_llm_result = self._item_name_extractor.extract_item_name(
        original_query, chat_history
    )
    item_names = clean_llm_result.get("item_names")
    rewritten_query = clean_llm_result.get("rewritten_query")

    # 3. 向量对齐
    if item_names:
        confirmed, options = self._item_name_aligner.match_align_filter(item_names)
    else:
        confirmed, options = [], []

    # 4. 决定 state
    self._decide(state, confirmed, options, rewritten_query)

    # ★ 新增：将历史对话写入 state，供下游 answer_output 使用
    state["history"] = chat_history

    return state


```

### 3.7 代码构建

在第二步基础上，加入 `_format_chat_history`、`_save_history`，以及 `_build_prompt` 中对历史对话的引用：

```python
from typing import List, Dict, Any, Tuple
from knowledge.processor.query_processor.base import BaseNode, T
from knowledge.processor.query_processor.state import QueryGraphState
from knowledge.utils.task_util import set_task_result
from knowledge.utils.sse_util import push_sse_event, SSEEvent
from knowledge.prompts.query_prompt import ANSWER_PROMPT
from knowledge.utils.client.ai_clients import AIClients
from knowledge.utils.mongo_history_util import save_chat_message


class AnswerOutputNode(BaseNode):

    def process(self, state: QueryGraphState) -> QueryGraphState:
        # 1. 获取任务id 以及流式开关
        task_id = state.get('task_id')
        is_stream = state.get('is_stream')

        # 2. 获取state的答案(已有答案)
        if state.get("answer"):
            # 2.1 推送answer
            self._push_existing_answer(state, task_id, is_stream)
            has_streamed = False

        # 3. 暂未有答案(经过三路检索完)
        else:
            # 3.1 构建提示词
            prompt = self._build_prompt(state)
            state['prompt'] = prompt

            # 3.2 生成答案
            self._generate_answer(prompt, state)
            has_streamed = is_stream

        # 4. 写入历史对话
        self._save_history(state)

        # 5. 流式模式发送结束事件
        if is_stream:
            if has_streamed:
                push_sse_event(task_id, SSEEvent.FINAL, {})
            else:
                push_sse_event(task_id, SSEEvent.FINAL, {"answer": state.get("answer", "")})

        return state

    def _push_existing_answer(self, state: QueryGraphState, task_id: str):

        """
        推送已存在的答案
        Args:
            state:

        Returns:

        """

        # 1. 如果不是流式输出
        if not state.get("is_stream"):
            set_task_result(state["task_id"], "answer", state.get("answer"))

    def _build_prompt(self, state: QueryGraphState) -> str:
        """
        构建提示词
        Args:
            state:

        Returns:

        """

        char_budget = self.config.max_context_chars

        # 1.  格式化用户问题以及商品名
        question = state.get('rewritten_query')
        item_names = state.get('item_names') or []

        # 2. 格式化检索上下文
        format_context_str, char_budget = self._format_reranked_doc(state.get("reranked_docs") or [], char_budget)

        # 3. 格式化历史对话
        format_history_str, char_budget = self._format_history(state.get('history') or [], char_budget)

        # 4. 格式化提示词
        return ANSWER_PROMPT.format(context=format_context_str or "暂无上下文",
                                    history=format_history_str or "暂无历史对话",
                                    item_names=",".join(item_names),
                                    question=question)

    def _format_reranked_doc(self, reranked_docs: List[Dict[str, Any]], char_budget: int) -> Tuple[str, int]:
        """
        格式化重排序后的文档
        Args:
            reranked_docs:  重排序后的文档
            char_budget:    总字符预算

        Returns:
            格式化后别的重排序文档,以及剩下可用字符
        """

        formatted_lines = []
        used_chars = 0
        # 1. 遍历格式化后的文档
        for index, doc in enumerate(reranked_docs):

            # 1.1 获取内容
            content = doc.get('content', '')

            # 1.2 判断内容是否存在
            if not content:
                continue

            # 1.3 构建元数据
            content_meta = [f"[{index}]"]

            # 1.3.1 拼接元数据
            for meta_field, template in [("source", "[source={}]"),
                                         ("chunk_id", "[chunk_id={}]"),
                                         ("url", "[url={}]"),
                                         ("title", "[title={}]")]:
                # a. 获取元数据字段值
                meta_field_value = str(doc.get(meta_field, '')).strip()

                # b. 填充模版变量
                if meta_field_value:
                    content_meta.append(template.format(meta_field_value))

            # 1.4 获取分数
            doc_score = doc.get('score')
            if doc_score is not None:
                content_meta.append(f"[score={float(doc_score):.4f}]")

            # 1.5 构建完整文档
            doc_entry = " ".join(content_meta) + "\n" + content

            # 1.6 分隔符长度
            seperator_usage = 2 if formatted_lines else 0

            # 1.7 计算总长度
            total_usage = seperator_usage + len(doc_entry)
            if used_chars + total_usage > char_budget:
                break

            # 1.8 将当前行加入
            formatted_lines.append(doc_entry)
            used_chars += total_usage

        return "\n\n".join(formatted_lines), char_budget - used_chars

    def _format_history(self, history: List[Dict[str, Any]], char_budget: int) -> Tuple[str, int]:
        """
        格式化历史对话
        Args:
            history: 历史对话
            char_budget:

        Returns:

        """

        formatted_lines = []
        used_chars = 0
        # 1. 遍历格式化后的文档
        role_map = {"user": "用户", "assistant": "助手"}
        for msg in history:
            # 1.1 获取消息角色
            role = msg.get('role', '')

            # 1.2 获取消息内容
            text = msg.get('text', '')

            # 1.3 获取格式化后的行
            if not text or role not in role_map:
                continue

            formatted_line = f"{role_map[role]}: {text}"

            # 1.4 计算分割符长度
            seperator_usage = 1 if formatted_lines else 0

            # 1.5 计算总长度
            total_usage = seperator_usage + len(formatted_line)

            if used_chars + total_usage > char_budget:
                break

            formatted_lines.append(formatted_line)
            used_chars += total_usage

        return "\n".join(formatted_lines), char_budget - used_chars

    def _generate_answer(self, prompt: str, state: QueryGraphState):
        """
        生成答案
        Args:
            prompt: 提示词
            state:  查询状态

        Returns:LLM输出内容

        """

        # 1. 获取LLM客户端
        try:
            llm_client = AIClients.get_openai_llm(response_format=False)
        except ConnectionError as e:
            self.logger.error(f"LLM客户端连接失败 异常原因:{str(e)}")
            state["answer"] = "LLM生成回答时出现错误"
            return

        # 2. 获取任务id
        task_id = state.get('task_id')
        # 3. 获取流开关
        is_stream = state.get('is_stream')

        if is_stream:
            state["answer"] = self._stream_generate(llm_client, prompt, task_id)
        else:
            state["answer"] = self._invoke_generate(llm_client, prompt)
            set_task_result(task_id, "answer", state["answer"])

    def _stream_generate(self, llm_client, prompt: str, task_id: str) -> str:
        """
        流式生成
        Args:
            llm_client:  llm客户端
            prompt:  提示词
            task_id:  任务id

        Returns:

        """

        # 1. 全量答案
        accumulate_answer = ""
        try:
            for chunk in llm_client.stream(prompt):
                # 1.1 获取增量
                delta_text = getattr(chunk, "content", "") or ""

                # 1.2 如果增量有
                if delta_text:
                    accumulate_answer += delta_text
                    push_sse_event(task_id=task_id,
                                   event=SSEEvent.DELTA,
                                   data={"delta": delta_text}
                                   )

        except Exception as e:
            self.logger.error(f"流式生成出错: {e}")
        return accumulate_answer

    def _invoke_generate(self, llm_client, prompt: str) -> str:
        try:
            response = llm_client.invoke(prompt)
            return response.content
        except Exception as e:
            self.logger.error(f"生成回答出错: {e}")
            return "抱歉，生成回答时出现错误。"

    def _save_history(self, state: QueryGraphState):
        """
        保存历史对话
        Args:
            state:

        Returns:

        """

        # 1. 获取用户问题
        user_query = state.get('rewritten_query')

        # 2. 获取item_names
        item_names = state.get('item_names') or []

        # 3. 获取answer
        answer = state.get('answer')

        # 4. 获取session_id
        session_id = state.get('session_id')

        # 5. 保存聊天信息
        try:

            if answer:
                # 5.1 保存用户角色信息
                save_chat_message(session_id=session_id,
                                  role="user",
                                  text=state.get('original_query'),
                                  rewritten_query=user_query,
                                  item_names=item_names,
                                  message_id=None)

                # 5.2 保护助手消息
                save_chat_message(session_id=session_id,
                                  role="assistant",
                                  text=answer,
                                  rewritten_query=user_query,
                                  item_names=item_names,
                                  message_id=None)
        except Exception as e:
            self.logger.error(f"保存历史对话失败 原因:{str(e)}")

```

> **为什么统一在 answer_output 写入？** `item_name_confirm_node` 专注于商品确认（只读 MongoDB ），`answer_output` 作为 pipeline 最终出口统一写入新记录，职责更清晰。

## 4. 对接查询前端（第三部分）

### 4.1 整体架构

<img src="images/6.前后端交互.jpg" style="zoom:50%;" />

> **导入侧用轮询，查询侧用 SSE，为什么不统一？** 导入流程耗时几十秒到几分钟，轮询间隔 1.5 秒足够；查询流程需要 LLM 逐字输出（几十毫秒一个 token），轮询无法满足实时性要求，必须用 SSE 长连接。

### 4.2 session_id vs task_id

```
session_id：标识一个会话（多轮对话共享，存历史记录用）
  - 前端页面加载时生成一次，存 localStorage
  - 同一浏览器标签页的所有对话共用

task_id：标识一次提问（任务状态、SSE 队列、进度追踪用）
  - 每次提问后端生成新的 task_id
  - 避免同一 session 下多次查询的状态互相覆盖
```

如果不分离，同一个 session 下连续两次提问，第二次的 `_tasks_running_list` 和 `_tasks_done_list` 会覆盖第一次的数据，导致进度混乱。

### 4.4 SSE 流式推送机制

#### 4.4.0 什么是 SSE

**SSE (Server-Sent Events)** 是一种服务器向客户端推送数据的技术。

```
┌─────────────────────────────────────────────────────────────────┐
│                      普通 HTTP 请求                               │
├─────────────────────────────────────────────────────────────────┤
│  客户端 ─────请求──────> 服务器                                   │
│         <─────响应──────      │                                 │
│                              │  一次请求，一次响应                │
│                              │  服务器无法主动推送                 │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                         SSE (本方案)                             │
├─────────────────────────────────────────────────────────────────┤
│  客户端 ─────建立连接─────> 服务器                                 │
│         <─────推送消息1──────      │                              │
│         <─────推送消息2──────      │  长连接，服务器持续推送        │
│         <─────推送消息3──────      │                              │
│                              │                                 │
└─────────────────────────────────────────────────────────────────┘
```

**为什么用 SSE？**

| 对比项     | 轮询               | WebSocket | SSE            |
| ---------- | ------------------ | --------- | -------------- |
| 实现复杂度 | 简单               | 复杂      | **简单**       |
| 服务器推送 | ❌ 需客户端反复请求 | ✅         | ✅              |
| 单向推送   | ❌                  | 双向      | ✅ **够用**     |
| 自动重连   | ❌                  | ❌         | ✅ **原生支持** |

> **一句话**：我们只需要服务器向客户端推送进度和答案，SSE 最简单、浏览器原生支持、自动重连。

#### 4.4.3 核心机制：Queue 解耦生产者和消费者

<img src="images/7.Queue 解耦生产者和消费者.jpg" style="zoom:50%;" />

> **为什么 sse_generator 用 `run_in_executor`？** `stream_queue.get` 是阻塞操作，直接在 async 函数中调用会卡死整个 FastAPI 事件循环。`run_in_executor` 把阻塞操作扔到线程池。

> queue.Queue.get() 是一个同步阻塞方法。如果在异步代码中直接调用，会阻塞整个事件循环。
>
>  使用 run_in_executor 把这个阻塞操作放到线程池中执行，避免阻塞事件循环，同时保持异步代码的流畅性。
>
> **为什么设 1 秒超时？** 不设超时则 `get` 无限等待，客户端断开了也检测不到。1 秒超时后回到循环顶部检查 `is_disconnected()`，及时退出。

#### 4.4.4 任务追踪：三层职责分离

| 模块 | 职责 | 依赖 |
|------|------|------|
| `task_utils.py` | 纯状态管理（增删查） | 无外部依赖 |
| `sse_utils.py` | 纯 SSE 队列和推送 | 无外部依赖 |
| `BaseNode` | 编排两者：状态更新 + 判断是否推送 | 依赖 task_utils + sse_utils |

`task_utils` 不知道 SSE 的存在，导入侧完全不受影响。

> **每次推送全量快照而非增量**：`done_list` 和 `running_list` 每次都完整推送，前端直接覆盖渲染。即使中间某条 progress 丢了，下一条也能正确显示。

def create_app() -> FastAPI:
    app = FastAPI(title="Query Service", description="知识库查询服务")
    app.add_middleware(
        CORSMiddleware,
        allow_origins=["*"],
        allow_credentials=False,
        allow_methods=["*"],
        allow_headers=["*"],
    )
    front_page_dir = get_front_page_dir()
    if front_page_dir and os.path.exists(front_page_dir):
        app.mount("/front", StaticFiles(directory=front_page_dir))

def register_routes(app: FastAPI):
    @app.get("/chat.html")
    async def chat_page():
        path = os.path.join(get_front_page_dir(), "chat.html")
        if not os.path.exists(path):
            raise HTTPException(status_code=404, detail="chat.html not found")
        return FileResponse(path)

    @app.post("/query")
    async def query(
            request: QueryRequest,
            background_tasks: BackgroundTasks,
            service: QueryService = Depends(get_query_service),
    ):

        # 1. 获取session_id
        session_id = request.session_id or service.generate_session_id()

        # 2. 获取任务_id
        task_id = service.generate_task_id()

        # 3. 开启流式
        if request.is_stream:
            # 3.1 必须在返回响应前创建队列，否则前端请求 /stream 时队列不存在
            create_sse_queue(task_id)

            # 3.2 后台运行graph
            background_tasks.add_task(
                service.run_query_graph, task_id, session_id, request.query, True
            )

            # 3.3 返回响应
            return StreamSubmitResponse(
                message="Query submitted", session_id=session_id, task_id=task_id
            )

        # 4. 非流式：丢到线程池避免阻塞事件循环
        loop = asyncio.get_running_loop()
        await loop.run_in_executor(
            None, service.run_query_graph, task_id, session_id, request.query, False
        )

        # 5. 获取答案
        answer = service.get_answer(task_id)

        # 6. 返回答案
        return QueryResponse(message="处理完成", session_id=session_id, answer=answer)

    @app.get("/stream/{task_id}")
    async def stream(task_id: str, request: Request):

            sse_generator(task_id, request), media_type="text/event-stream",
        )

    @app.get("/history/{session_id}")

            session_id: str, limit: int = 50,
            service: QueryService = Depends(get_query_service),
    ):
        try:
            items = service.get_history(session_id, limit)

#### 4.7.7 sse_utils.py

```python
import json
import queue
import asyncio
from typing import Dict, Any, Optional, AsyncGenerator
from fastapi import Request


class SSEEvent:
    READY = "ready"         # 连接建立
    PROGRESS = "progress"   # 任务节点进度
    DELTA = "delta"         # LLM 流式输出增量
    FINAL = "final"         # 最终完整答案


# 全局 SSE 任务队列存储
# Key: task_id, Value: queue.Queue
_task_stream: Dict[str, queue.Queue] = {}


def get_sse_queue(task_id: str) -> Optional[queue.Queue]:
    """获取指定任务的队列"""
    return _task_stream.get(task_id)


def create_sse_queue(task_id: str) -> queue.Queue:
    """创建并注册一个新的 SSE 队列"""
    q = queue.Queue()
    _task_stream[task_id] = q
    return q

def remove_sse_queue(task_id: str):
    """移除指定任务的队列
    不存在 key 默认返回 None
    """
    _task_stream.pop(task_id, None)


def _sse_pack(event: str, data: Dict[str, Any]) -> str:
    """打包 SSE 消息格式"""
    payload = json.dumps(data, ensure_ascii=False)
    return f"event: {event}\ndata: {payload}\n\n"


def push_sse_event (task_id: str, event: str, data: Dict[str, Any]):
    """
    通过 task_id 推送事件到 SSE 队列
    """
    # 1. 获取 SSE 队列
    stream_queue = get_sse_queue(task_id)

    # 2. 队列存在
    if stream_queue:
        # 3. 将事件推送到队列
        stream_queue.put({"event": event, "data": data})


async def sse_generator(task_id: str, request: Request) -> AsyncGenerator[str, None]:
    """
    SSE 生成器，用于 FastAPI 的 StreamingResponse
    """
    # 1. 获取队列
    stream_queue = get_sse_queue(task_id)

    # 2. 如果没有对应的队列，直接结束
    if stream_queue is None:
        return

    # 3. 获取当前运行的异步事件循环（用于后续将同步阻塞代码放入线程池执行）
    loop = asyncio.get_running_loop()
    try:

        while True:
            # 4. 服务端检测客户端断开，尽快退出
            if await request.is_disconnected():
                break
            try:
                # 5. 使用 run_in_executor 避免阻塞 async 事件循环
                # block=True: 如果队列为空，是否阻塞等待
                # timeout=1.0: 阻塞的超时时间（秒），1.0 秒后若仍无数据则抛出 queue.Empty 异常
                msg = await loop.run_in_executor(None, stream_queue.get, True, 1.0)
                
            except queue.Empty:
                # 6. 若 1 秒内队列为空（超时），则跳过本次循环，重新开始检查断开状态并继续监听
                continue
                
            # 7. 解析队列中获取到的消息体
            event = msg.get("event")
            data = msg.get("data")
            # 8. 将正常的事件和数据打包成标准 SSE 格式，并通过 yield 推送给前端客户端
            yield _sse_pack(event, data)

    except (ConnectionResetError, BrokenPipeError):
        # 客户端强行刷新页面或关闭标签页，TCP 管道破裂，静默退出
        return
    except asyncio.CancelledError:
        # 服务端中断 协程被取消：重新抛出，让外层知道它被成功取消了
        raise
    finally:
        # 清理资源（防止内存泄漏）
        remove_sse_queue(task_id)
```





## 5. 常见问题与排查

### 5.1 流式模式下按钮一直禁用

**症状**：答案生成完了，但发送按钮一直灰色不可点击。

**原因**：`FINAL` 事件和 `progress(completed)` 都没到达前端。可能是 `answer_output` 抛异常且 `query_service.finally` 也没执行到推送。

**排查**：检查后端日志是否有 `查询流程执行失败` 的错误。

### 5.2 并行节点报 INVALID_CONCURRENT_GRAPH_UPDATE

**症状**：`At key 'session_id': Can receive only one value per step.`

**原因**：并行节点的 `process` 方法返回了 `return state`（整个 state），多个节点同时写 `session_id` 导致冲突。

**修复**：并行节点只返回自己修改的字段：

```python
# 错误
return state

# 正确
return {"embedding_chunks": response[0]}
```

### 5.3 节点进度条中文名显示不正确

**症状**：前端进度条显示英文节点名。

**原因**：`_NODE_NAME_TO_CN` 的 key 与 `BaseNode.name` 不一致。

**修复**：确保 `main_graph` 的 key、`BaseNode.name`、`_NODE_NAME_TO_CN` 三者统一。

## 6. 总结

### 6.1 代码构建步骤回顾

| 步骤 | 内容 | 涉及文件 |
|------|------|---------|
| 第一步 | 骨架：主流程 + 提示词组装 + 非流式生成 | answer_output.py |
| 第二步 | +流式生成 + FINAL 推送 + 已有答案处理 | answer_output.py |
| 第三步 | +历史对话格式化 + MongoDB 写入 + item_name_confirm 改造 | answer_output.py + item_name_confirm_node.py |
| 第四步 | Schema + Service + Router + BaseNode + task_utils | 6 个新文件 |

### 6.2 设计要点

1. **职责分离**
   - `item_name_confirm_node` 只读 MongoDB（查历史 + 回填）
   - `answer_output` 统一写 MongoDB（用户问题 + 助手回答）
   - 查询侧架构与导入侧完全对称（Router/Schema/Service/Deps）

2. **SSE 推送三层解耦**
   - `task_utils` 管状态，不知道 SSE 存在
   - `sse_utils` 管推送，不知道任务状态存在
   - `BaseNode` 是唯一知道两者的地方，负责协调

4. **并行节点只返回自己修改的字段**
   - `return state` 会导致多个并行节点同时写共享字段
   - 正确做法是 `return {"my_field": my_value}`

5. **session_id 和 task_id 各司其职**
   - `session_id` 跟随浏览器标签页生命周期，多轮对话共享
   - `task_id` 跟随单次提问生命周期，用完即弃
   - MongoDB 历史用 `session_id` 存，任务状态和 SSE 队列用 `task_id` 管
